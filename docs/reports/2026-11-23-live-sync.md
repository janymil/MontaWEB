## 4. What was done

1. **Backup:** annotated tag `backup/pre-live-sync-2026-11-23` at `6b9dc9e`; local copy of `api/config.php` saved to `%TEMP%` during the work. Ignored files (`api/config.php`, `.claude/worktrees/`) were never touched.
2. **Added the live repo as a remote** in the local repo:
   `git remote add live ssh://washington/var/www/montaweb`
3. **Fetched and fast-forwarded** `main` to the live HEAD: `git fetch live main && git merge --ff-only live/main` → local `main` = `d6741c8`.
4. **Byte-exact working tree:** the Windows checkout had CRLF line endings, so files were materialized from the committed blobs with `git -c core.autocrlf=false archive` and extracted with Python's `tarfile` (UTF-8-safe; Windows `tar.exe` mangled `diseño-web-lima.html` into a mojibake duplicate, which was removed). The index stat cache was refreshed with `git add -u`; the global/system `core.autocrlf=true` setting was **not** changed.
5. **Applied live's uncommitted change:** copied `/var/www/montaweb/CLAUDE.md` (1 121 B, devkit block) down.
6. **Copied `api/vendor/`** (autoload + PHPMailer) so the local PHP endpoint has its dependencies.
7. **Verified** (see §5) and removed temporary files.

## 6. Remaining differences and notes

1. **`api/config.php` is intentionally not synced.** It contains live SMTP/Zoho credentials, is gitignored, and the local copy already has its own dev config. Everything else in the live app is byte-identical. If you ever want the local file to mirror live, copy it manually — but do not commit it.
2. **Local-only tooling:** `.claude/worktrees/` (git worktrees used by earlier agent sessions) was excluded from comparison/sync; it is not website content. `scripts/compare-live.py` and this report are new untracked files — commit them if useful (they are the only two entries the compare script reports as "only local").
3. **Line endings:** the working tree now holds LF bytes exactly as live. Because the repo/system `core.autocrlf=true` is unchanged, a future `git checkout` may rewrite text files to CRLF; content stays identical but raw hashes will then differ. Use the compare script for content checks.
4. **GitHub is now aligned.** `main` was pushed `5e78266..d6741c8` (fast-forward, no force) using the `gh` CLI credentials; `origin` was repointed to `https://github.com/janymil/MontaWEB.git` to drop the renamed-repo redirect. GitHub's committed tree does **not** include live's uncommitted `CLAUDE.md` devkit block (see item 8).
5. **Known red tests on live** (`clinica.html`, `restaurante.html`). If you want green tests, the fix is a dev change to `test/pages-have-go-up.test.mjs` (skip redirect stubs) — that would deliberately diverge from live, so it was not done here.
6. **Deploy discipline:** this folder is now the dev copy. Do not edit `/var/www/montaweb` directly; deploy local changes per `DEPLOY.md` (commit → push/pull or the deploy procedure), and keep using the live server as production.
7. **Restore point:** `git reset --hard backup/pre-live-sync-2026-11-23` returns the tracked tree to the pre-sync local state (`6b9dc9e`). The `live` remote (`ssh://washington/var/www/montaweb`) remains for future `git fetch live main`.
8. **Only remaining content-level gap anywhere:** the `devkit` block in `CLAUDE.md` exists as an uncommitted modification on both local and Washington, so it is in no git commit — all three repos' commits are identical at `d6741c8`. Committing it would make GitHub's tree match the working copies, but would also require pulling that commit on Washington to keep all three at the same commit; deliberately left undone to avoid changing the live repo state without asking.
